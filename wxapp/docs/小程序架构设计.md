# 小程序架构设计（家长端 / 学生端）

> 技术栈：uni-app（Vue 3）→ 微信小程序 mp-weixin
> 目标：**快速上线 + 靠分享裂变拿到用户**，功能一点点加，不要一上来设计死。

---

## 1. 定位与增长模型

这是一个人的家教业务，用户是**家长和学生**。小程序的角色不是"又一个管理后台"，
而是老师的**内容分发渠道**：题库是现成的资产，把它变成能被转发的内容。

增长闭环：

```
老师/家长在群里分享「一道题」
        ↓
对方点开 → 冷启动直达单题详情（无登录墙，直接能看）
        ↓
看完解析 → 底部「回到题库」 → 看到 123 道题按知识点排好
        ↓
留存（后续接入：作业 / 成绩 / 错题本）
```

由此推出三条硬约束：

| 约束 | 设计决定 |
| --- | --- |
| 分享出去的链接必须能直接打开 | 单题详情页是一等公民，自带 `onShareAppMessage` + `onShareTimeline` |
| 点进来不能有登录墙 | 首屏零鉴权感知，访客令牌在后台静默换取 |
| 包要小、首屏要快 | 不引三方 UI 库，主包控制在 KB 级 |

---

## 2. 分层架构

```
┌─ 展示层  pages/        题库列表 · 单题详情（分享落地页）
├─ 组件层  components/   题目卡片 · 富文本块 · 空/错误态
├─ 状态层  store/        访客会话 · 题库上下文（翻页）
├─ 接口层  api/ + utils/ request（令牌/重试）· richtext · latex · storage
└─ 服务端  /api/open/*   只读路由组，中间件层强制 GET/HEAD
```

规则（避免以后变乱）：

- **页面只做编排**，不写请求细节，一律走 `api/`。
- **富文本只有 `components/rich-block` 一个出口**，别在页面里直接写 `<rich-text>`，
  否则图片自适应和公式降级的行为会不一致。
- **跨页面共享的数据才进 store**，页面内部状态留在 `data` 里。
- **小程序不写任何数据**，增删改全在 Web 管理后台。

## 3. 目录结构

```
wxapp/
├── config/index.js              # 环境配置（dev/prod）+ PAGE_SIZE + 缓存时长
├── utils/
│   ├── request.js               # 访客令牌 + 401 重签 + 解包 {code,message,data}
│   ├── richtext.js              # 富文本清洗：图片自适应 / 公式降级 / 纯文本提取
│   ├── latex.js                 # LaTeX → 可读文本（零依赖）
│   ├── storage.js               # 带 TTL 的本地缓存
│   └── constants.js             # 题型 / 难度 / 选项字母
├── api/question.js              # 题库接口（只读）
├── store/index.js               # 列表上下文 + 搜索历史
├── components/
│   ├── rich-block/              # 富文本唯一出口
│   ├── question-card/           # 列表卡片
│   └── empty-state/             # 空态 / 错误态
├── pages/
│   ├── bank/list.vue            # 题库首页（列表 + 知识点两个视图）
│   └── bank/detail.vue          # 单题详情（分享落地页）
└── pages.json                   # 路由表 = 功能注册表
```

## 4. 路由

| 路径 | 作用 | 备注 |
| --- | --- | --- |
| `pages/bank/list` | 题库首页，启动页 | 开下拉刷新；支持触底加载 |
| `pages/bank/detail?id=123` | 单题详情 | **分享落地页**，可冷启动直达 |

加新功能 = 在 `pages.json` 的 `pages` 数组里加一项 + 建一个页面，
不改动任何导航代码。等页面超过 4~5 个、需要第 3 个以上的一级入口时，
再引入 `config/features.js` 功能注册表 + 首页宫格也不迟——现在加是过度设计。

## 5. 鉴权与安全（本次最重要的改动）

### 之前的问题

旧版 `utils/request.js` 把**管理员账号密码写进了小程序包**。
小程序包可以被反编译，等于把整个题库的增删改权限公开挂在群里分享出去。

### 现在的做法：只读访客令牌

```
小程序 ──POST /api/auth/guest──▶ 签发 scope=guest 令牌（7 天）
       ──GET  /api/open/questions…──▶ 只有读权限
```

三层防护，任一层单独失效都不会出事：

1. **路由隔离**：`/api/open/*` 是独立路由组，只登记查询 handler，写接口根本不在里面。
2. **中间件强制只读**：`requireReadonly` 对非 GET/HEAD 直接返回 405。
   即使将来手滑挂了个 POST 上去，也改不了数据。
3. **令牌无管理员身份**：guest 令牌访问 `/api/questions`（管理员路由）返回 401。

服务端配置（`server/.env`）：

```bash
GUEST_CODE=          # 留空 = 只读接口完全开放；填了则小程序必须带同样的码
GUEST_TOKEN_TTL_MS=604800000
```

小程序侧对应 `config/index.js` 的 `GUEST_CODE`。

> 已验证：无令牌 401、POST 405、DELETE 405、guest 令牌访问管理员路由 401。

## 6. 富文本与公式（关键决策）

题干是富文本 HTML，公式以 `$...$` 原文存库，Web 端靠 KaTeX 的 CSS 渲染。

**问题**：小程序 `<rich-text>` 跑在隔离环境里，外部样式表不生效。
KaTeX 吐出的那一堆 `class="katex mord vlist"` 会全部塌掉，
显示效果还不如纯文本，还会多背 270KB 的 katex 体积。

**决定**：零依赖的 `utils/latex.js`，把中学数学常用子集转成 Unicode / 类 ASCII：

| 源码 | 渲染 |
| --- | --- |
| `$\alpha(0<\alpha<1)$` | α(0<α<1) |
| `$x_{1}+x_{2}=-\frac{b}{a}$` | x₁+x₂=-(b)/(a) |
| `$\sum_{i=1}^{n} i^2$` | Σ(i=1→n) i² |
| `$\lim_{x \to 0} \frac{\sin x}{x}=1$` | lim(x → 0) (sin x)/(x) = 1 |
| `$\left(\frac{1}{2}\right)^{n}$` | ((1)/(2))ⁿ |
| `$\{x\mid x^2-3x+2<0\}$` | {x\| x²-3x+2<0} |

已覆盖希腊字母、上下标、分数、根式、求和积分极限、集合逻辑、几何符号、三角对数名。
覆盖不到的命令退化成去反斜杠的原文，不会满屏 `$` 和 `\`。

**全量校验**：123 道真实题目跑一遍，残留未识别命令 / 双重转义 / 孤立 `$` 的数量为 **0**。

### 踩过的坑（别改回去）

处理顺序必须是 **解码 HTML 实体 → 转公式 → 重新转义**。
题干里的小于号存的是 `&lt;`，如果直接转公式，`convert()` 会把 `&` 当成
LaTeX 的表格对齐符，`$a&gt;b$` 会变成 `a  gt;b`。

### 图片

- 相对路径自动补 `config.OSS_BASE` 前缀；
- 强制 `max-width:100%;height:auto`（题库图片多是题目截图，宽度失控最常见）；
- rich-text 内部是 webview 渲染，样式要用 **px**，rpx 在这里不生效；
- rich-text 不支持图片点击，所以详情页额外收集所有图片地址，
  提供「查看原题图」用 `uni.previewImage` 放大。全库 42 道题有图，值得这个入口。

### 后续升级路径

要做真正的公式排版，正确方向是引入 **mp-html + 它的 katex 插件**
（mp-html 用真实组件渲染节点，组件 wxss 生效），而不是继续在 rich-text 上打补丁。

## 7. 增长设计

| 能力 | 实现位置 | 说明 |
| --- | --- | --- |
| 单题分享到会话/群 | `detail.vue` `onShareAppMessage` | 底部 `open-type="share"` 按钮 + 右上角菜单 |
| 分享到朋友圈 | `onShareTimeline` | `query: id=xxx` |
| 分享标题 | ```知识点｜题干前 24 字``` | 自动从富文本提取纯文本 |
| 分享配图 | `imageUrl` 取题目第一张图 | 无图时留空，微信自动截页面 |
| 冷启动直达 | `detail?id=` 路径 | 无上下文时隐藏上下题，显示「回到题库」 |
| 无登录墙 | 访客令牌静默换取 | 点开即看，0 步操作 |

分享是这个功能的主要获客渠道，所以**详情页承载了题库的全部内容**，
列表页只放题干和标签——这样每一次转发都是一个完整可用的内容单元。

## 8. 性能与包体预算

| 项 | 目标 | 现状 |
| --- | --- | --- |
| 主包体积 | < 1 MB | 零三方依赖，KB 级 |
| 首屏 | 先出内容，不等二次请求 | 列表与知识点统计并发请求 |
| 分页 | 10 条/页，触底加载 | `config.PAGE_SIZE` |
| 知识点数据 | 本地缓存 5 分钟 | `utils/storage` TTL 缓存 |
| setData | 只传视图需要的字段 | `bankContext` 只存 id 数组，不存题目对象 |
| 搜索 | 300ms 防抖 | 避免每敲一个字打一次请求 |

## 9. 加下一个功能的正确姿势

1. `pages.json` 加一项路由；
2. 建 `pages/<模块>/<页面>.vue`；
3. 需要接口就在 `api/` 下加一个文件，写接口一律走 `utils/request`；
4. 需要跨页面共享的状态才放进 `store/`；
5. 涉及富文本就用 `<rich-block>`，别自己写 `<rich-text>`。

**不要**一开始就抽 `features.js` 注册表、不要引 UI 组件库、不要上 TypeScript。
等真的有第 4 个页面了，重构成本远低于现在的维护成本。

## 10. 上线 checklist

### 提交审核前

- [ ] `config/index.js` 的 `isProd` 改成 `true`，`API_BASE` 换成 https 域名
- [ ] `manifest.json` → `mp-weixin.appid` 填上正式 AppID
- [ ] `manifest.json` → `mp-weixin.setting.urlCheck` 改回 `true`
- [ ] `manifest.json` 里的 `app-plus` / `quickapp` / `mp-alipay` 等无关配置删掉
- [ ] 微信公众平台 → 服务器域名：
      - `request 合法域名`：API 域名
      - `downloadFile 合法域名`：**OSS 域名必须加**，否则题目图片全显示不出来
- [ ] `server/.env` 设置 `AUTH_SECRET`（别用默认的 `dev-only-change-me`）
- [ ] `server/.env` 按需设置 `GUEST_CODE`
- [ ] 真机测一遍：iOS + Android 各一台，重点看公式和图片

### 审核风险点（重点）

- [ ] **类目资质**：这是最大的不确定项。教育类目在微信通常需要机构资质，
      个人主体可选类目受限。去公众平台「设置 → 基本设置 → 服务类目」
      确认你当前的主体能选哪个类目，再决定是挂「教育」还是「工具」。
      **这一步建议在做完域名配置后第一件事就去确认**，它决定整个审核策略。
- [ ] 隐私协议：本小程序不采集任何用户信息，但仍需在公众平台配置
      「用户隐私保护指引」并声明不收集，否则涉及隐私接口的调用会被拦。
- [ ] 分享文案：不要在分享标题里用「最全」「第一」等极限词。
- [ ] 内容合规：题库内容若含高考真题，注意版权表述，别写「官方真题」之类。

### 上线后

- [ ] 观察「分享次数 / 分享打开率」，这是唯一的获客漏斗
- [ ] 观察单题详情的平均停留时长，判断解析质量
- [ ] 按知识点维度的点击分布，反哺 Web 后台的录题优先级

## 11. 已知限制

- 公式是**降级渲染**，不是真正的数学排版。复杂矩阵、多行对齐公式会不好看。
- rich-text 内的图片不能点击放大，详情页的「查看原题图」是绕过去的方案。
- 目前所有访客看到的是同一份题库，没有按学生隔离。若要按学生分发，
  需要新增家长绑定（openid ↔ studentId），见 `docs/作业发布与下载_开发文档.md`。
- 题库内容对任何拿到小程序的人可见。若介意，把 `GUEST_CODE` 配上，
  只告诉目标家长——这是目前唯一的内容门槛。
