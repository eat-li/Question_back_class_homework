# 数学辅导小程序 · 开发开会文档（Kickoff）

> 版本：v1.0（2026-08-24）
> 定位：本文件是**对齐用**的开工文档，不是最终设计。核心诉求是「**架构留口子，功能一点点加**」，所以本文刻意不把页面/导航写死，而是定义一套可插拔的模块机制。
> 配套文档：`wxapp/docs/作业发布与下载_开发文档.md`（接口契约与联调细节，本文直接复用其接口结论）。

---

## 1. 目标与原则

**目标**：交付一个微信小程序，让学生 / 家长在手机上看到老师发布的内容。

**本期范围（最小可用）**：
1. 已发布作业：列表 + 题目查看（复用已有设计）
2. 学生成绩波动：个人成绩趋势折线

**设计原则（满足"不要设计得太死板"）**：
- **功能可插拔**：新功能 = 建一个页面 + 在 `config/features.js` 注册一条。导航、首页入口自动出现，不改散落代码。
- **分层解耦**：接口层 / 状态层 / 页面层 / 组件层各自独立；图表、请求等易变部分封装成可替换组件。
- **数据全用现有后端**：不新造接口（成绩波动直接用 `/api/grades/summary`），必要时再向后端提小需求。
- **身份从简**：本期不做复杂鉴权，先用最轻量的方式识别"我是哪个学生"，后续可平滑升级。

## 2. 用户视角与信息架构

```
小程序启动
   │
   ├─ 首次/未识别身份 → 身份选择页（从名册选自己，本地记住）
   │
   └─ 已识别 → 首页（功能宫格，由 config/features.js 驱动）
        ├─ [作业]       → 作业列表 → 作业详情/题目
        └─ [成绩波动]   → 个人成绩趋势
        （后续宫格里自动长出：错题本 / 家长反馈 / 课程表 ……）
```

- 首页用**宫格 / 列表**而非写死底部 tabbar，好处是加功能只改配置、不碰导航代码。
- 若后期功能变多，再把 `config/features.js` 里的 `tabbar:true` 项升级为原生 tabbar，迁移成本极低。

## 3. 身份方案（本期从简，留升级口）

**为什么需要**：成绩波动是按 `studentId` 拉取的，小程序得知道"当前是谁"。

**本期推荐方案（零后端改动）**：
- 启动页拉 `GET /api/students` 拿到名册（姓名 + 年级）。
- 学生首次打开，从名册里**点选自己的名字**（或个人中心输入姓名匹配），把 `studentId` 存到本地 `uni.setStorageSync('studentId', id)`。
- 之后所有请求自动带该 `studentId`。

**备选方案（老师分享入口）**：
- 老师在 Web 后台生成"XXX 的专属小程序链接 / 二维码"，带 `?sid=<id>`；小程序 `onLaunch` 读 query 直接定位身份。适合不想让学生翻名册的场景。

**后续升级路径（不本期做）**：
- 微信 `openid` 绑定学生（需后端加绑定接口 + 小程序登录），实现"打开即认人、换手机也在"。

> 决策点见 §8：用"名册点选"还是"老师分享链接"？两者代码量都小，建议先上名册点选。

## 4. 数据来源（真实后端，已核对）

| 用途 | 接口 | 关键返回 | 说明 |
|---|---|---|---|
| 身份名册 | `GET /api/students` | `[{id,name,grade}]` | 用于身份选择 |
| 作业列表 | `GET /api/homeworks` | `Homework[]` | 前端过滤 `status==='published'` |
| 作业题目 | `GET /api/homeworks/:id/questions` | `Question[]` | `title` 为富文本 HTML，用 `<rich-text>` 渲染 |
| **成绩波动** | `GET /api/grades/summary?studentId=X` | `{ trend, radar, distribution, compare }` | **用 `trend`**：按科目分组的时序 `{subject, points:[{date,examType,score,fullScore,percent}]}` |

> 成绩波动直接吃 `/grades/summary` 的 `trend` 字段，**无需新增后端接口**。展示口径建议用 `percent`（百分比，满分不同也可比）；数学单科为主，`subject` 基本恒为"数学"，后续可加科目切换。

## 5. 技术架构（经典 uni-app，模块化、可插拔）

### 5.1 目录结构（扩展版）

```
wxapp/
├── config/
│   ├── index.js          # API_BASE / OSS_BASE
│   └── features.js        # ★ 功能注册表（灵活性的关键）
├── utils/
│   └── request.js         # uni.request 封装 + 解包 {code,message,data}
├── api/
│   ├── homework.js
│   ├── grade.js
│   └── student.js
├── store/
│   └── student.js         # 当前学生身份（本地持久化，全局可读）
├── components/
│   ├── feature-grid.vue   # 首页宫格（读 features.js 渲染）
│   ├── homework-card.vue  # 作业卡片（复用）
│   ├── trend-chart.vue    # ★ 成绩趋势图（封装图表库，业务页不直连）
│   └── empty-state.vue
├── pages/
│   ├── index/
│   │   └── index.vue      # 首页：feature-grid
│   ├── identify/          # 身份选择页（本期新增）
│   │   └── index.vue
│   ├── homework/          # 作业模块
│   │   ├── list.vue
│   │   └── detail.vue
│   └── grade/             # 成绩模块
│       └── trend.vue
└── ...（manifest / pages.json / App.vue / main.js 等保持原状）
```

### 5.2 ★ 功能注册表 `config/features.js`（核心）

新增功能只动这一处 + 建页面，导航零改动：

```js
// wxapp/config/features.js
// 新增模块：1) 建 pages/<key>/ 页面 2) pages.json 注册 3) 在此加一项
export default [
  { key: 'homework', title: '作业',     icon: 'paperplane', page: '/pages/homework/list' },
  { key: 'grade',    title: '成绩波动', icon: 'trend',      page: '/pages/grade/trend' }
  // 后续直接追加，例如：
  // { key: 'wrong',    title: '错题本',   icon: 'close',  page: '/pages/wrong/list' },
  // { key: 'feedback', title: '家长反馈', icon: 'email',  page: '/pages/feedback/list' }
]
```

首页 `feature-grid.vue` 遍历该数组渲染入口；点击 `uni.navigateTo({ url: item.page })`。
图标用 `uni-icons`（线性图标），**不用 emoji**，与 Web 端审美一致。

### 5.3 分层职责

- **api/**：每个领域一个文件，只管拼 URL + 调 `request`，返回解包后的数据。
- **store/student.js**：`get/set` 当前学生；`getCurrent()` 读本地存储，`ensure()` 未识别则跳身份页。
- **components/**：纯展示 / 可复用；`trend-chart` 把图表库（建议 uCharts，小程序轻量友好）封在里面，将来换库不影响业务页。
- **pages/**：薄页面，只做"取数 → 传 props → 组合组件"。

## 6. 本期模块设计

### 6.1 作业模块（复用已有开发文档）
- `homework/list.vue`：拉 `GET /api/homeworks` → 过滤 `published` → `homework-card` 列表。
- `homework/detail.vue`：拉 `:id` 与 `:id/questions` → `<rich-text>` 渲染题干（OSS 图片可显示；KaTeX 公式见已知限制）。
- 不实现发布 / 批改 / 附件下载（留待后端加 `attachments` 后）。

### 6.2 成绩波动模块（本期新增）
- `identify/index.vue`：拉名册 → 点选 → 存 `studentId` → 跳首页。
- `grade/trend.vue`：
  - 取 `store/student` 的 `studentId` → `GET /api/grades/summary?studentId=X`。
  - 用 `trend`（按科目分组的时间序列）喂给 `<trend-chart>`：x 轴=日期，y 轴=百分比，每科目一条线。
  - 顶部展示：当前学生姓名、最近一次百分比、较上次涨跌（红涨绿跌，遵循国内习惯）。
  - 空数据 → `empty-state`。

```js
// api/grade.js 示例
import request from '@/utils/request'
export default {
  summary: (studentId) => request.get(`/grades/summary?studentId=${studentId}`)
}
```

## 8. 关键决策与待确认项

1. **身份识别**：名册点选（推荐，零后端改动） vs 老师分享链接（需生成带 `sid` 的入口）。→ 建议先名册点选。
2. **成绩口径**：趋势用 `percent`（百分比，推荐）还是原始分？→ 建议百分比。
3. **科目切换**：本期数学单科，是否要加科目下拉？→ 建议本期不做，趋势组件预留 `subject` 过滤。
4. **图表库**：uCharts（轻量、小程序原生友好，推荐） vs echarts-for-weixin。→ 建议 uCharts，封装在 `trend-chart` 内。
5. **视觉**：延续 Web 端克制风格（无 emoji、低饱和、无重阴影）；小程序配色从 `uni.scss` 变量派生一套。

## 10. 风险与备注

- **KaTeX 公式**：`<rich-text>` 不加载外部 CSS，含公式题目可能显示异常；题库录入时公式尽量以图片存储（OSS URL）。属已知限制，非本期阻塞。
- **无鉴权**：本期任何人拿到小程序都能看全量已发布作业与（选完身份后）某学生成绩；单用户自用可接受，正式扩散前需加身份/权限。
- **后端阻塞项仍有效**：作业附件下载依赖 `attachments` 字段 + 通用上传接口（见开发文档 §6），本期不涉及。
- **域名白名单**：`manifest` 的 `urlCheck:false` 仅开发期；上线前须在微信后台配 request / downloadFile 合法域名。
