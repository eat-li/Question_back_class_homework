# 项目优化建议

> 适用范围：教师辅助系统（client / server / wxapp）
> 建议性质：基于当前代码静态检查与常见工程实践整理，按优先级排列。
> 配套文档：`docs/design-optimization.md`（视觉优化）、`docs/PLANNING.md`（规划）

---

## 一、总体结论

当前项目功能完整、目录清晰，前后端分层明确，已经具备较好的可维护性。主要优化空间集中在：

1. **可靠性**：接口输入校验不足、数据库缺少唯一约束、备份不完整。
2. **性能**：多个列表接口全量返回，前端做内存分页；成绩导入/作业评分存在 N+1 或全表加载。
3. **安全**：`v-html` 未消毒、CORS 全开、错误信息可能外泄、AI Key 存在 `localStorage`。
4. **工程质量**：缺少统一错误提示、类型定义、公共逻辑抽取、lint/test/CI。

---

## 二、高优先级（建议近期完成）

### 1. 统一前端请求错误处理

**现状**：`client/src/api/request.ts` 只做了响应解包，没有统一弹出错误；多数页面 `await` 请求失败时没有 `catch`，容易产生未处理 Promise rejection，用户看不到明确失败原因。

**建议**：

- 在 axios 响应拦截器中统一处理 `code !== 0` 和 HTTP 错误：
  - 网络错误/超时提示“网络异常，请稍后重试”；
  - 业务错误提示 `message`；
  - 预留 401/403 跳转或提示。
- 使用 `ElMessage.error` 统一展示；页面中只处理需要特殊提示的业务逻辑。
- 可封装 `request<T>()` 泛型，让 API 层返回类型更明确。

**涉及文件**：`client/src/api/request.ts`、所有 `views/**`。

---

### 2. 服务端输入校验与字段白名单

**现状**：

- `Student.create(req.body)`、`Question.create(req.body)`、`Homework.create(req.body)` 直接写入请求体，存在“多余字段/非法字段被写入”的风险。
- `category.controller`、`conclusion.controller` 已做了 `pick()` 白名单，但没有推广到其他模块。

**建议**：

- 为每个模型建立 `pick(body)` 或 `validate(body)`，只允许写入定义字段。
- 对必填字段、字符串长度、数字范围、枚举值做统一校验。
- 将校验逻辑抽成独立 `validators/` 或 middleware，避免控制器臃肿。

**涉及文件**：

- `server/src/controllers/student.controller.js`
- `server/src/controllers/question.controller.js`
- `server/src/controllers/homework.controller.js`
- `server/src/controllers/grade.controller.js`

---

### 3. 数据备份必须“全量且可恢复”

**现状**：`server/src/controllers/backup.controller.js` 只导出 `Question / Homework / Student / Submission`，缺少：

- `ExamScore`（测评成绩）
- `KnowledgeCategory`（知识点分类）
- `Conclusion`（结论）

导致页面上宣传的“把全部题目、作业、学生名单和成绩打包”与实际备份范围不一致；重装后无法完整恢复。

**建议**：

- 备份接口导出全部业务表，至少包括 `Question, Homework, Student, Submission, ExamScore, KnowledgeCategory, Conclusion`。
- 增加“恢复接口” `/api/backup/restore`（或前端导入 ZIP），按依赖顺序写入：分类 → 学生 → 题目 → 作业 → 提交 → 成绩 → 结论。
- README.txt 中说明备份文件结构与恢复步骤。
- 增加备份文件版本号字段，便于后续兼容迁移。

**涉及文件**：`server/src/controllers/backup.controller.js`、`client/src/views/system/DataBackup.vue`。

---

### 4. 数据库唯一约束与索引补齐

**现状**：

- `ExamScore` 没有唯一索引，`grade.controller` 靠 `findOrCreate` 保证业务唯一，并发或手工插入仍可能产生重复成绩。
- `Submission` 没有 `(homework_id, student_id)` 唯一约束，重复保存成绩可能产生多条记录。
- 当前 `ensureIndexes` 已建单列索引，但缺少常用组合索引。

**建议**：

- 在模型中直接声明唯一约束，或在 `ensureIndexes` 中创建唯一索引：
  - `exam_scores(student_id, exam_type, subject, exam_date)`
  - `submissions(homework_id, student_id)`
- 根据查询模式补组合索引：
  - `exam_scores(student_id, exam_date)`
  - `exam_scores(exam_type, exam_date)`
  - `submissions(homework_id, student_id)`
  - `questions(knowledge_tag, type, difficulty)`
- 为 `Student.name` 是否应唯一做产品决策：如果导入以姓名为主键，建议加唯一约束或改用学号等稳定标识。

**涉及文件**：

- `server/src/models/ExamScore.js`
- `server/src/models/Submission.js`
- `server/src/utils/ensureIndexes.js`
- `server/src/controllers/grade.controller.js`

---

### 5. 列表接口分页 / 聚合，避免全量加载

**现状**：

- `GET /questions` 返回全部题目，`QuestionBrowse.vue` 在浏览器端 `allList.slice(...)` 做分页；题目量增大后首屏和查询都会变慢。
- `QuestionBank.vue` 为展示知识点卡片，一次性拉全量题目后在前端分组统计。
- `GET /students`、`GET /homeworks` 也没有分页；`GradeInput.vue` 同时加载全部学生和全部成绩。

**建议**：

- 为 `questions`、`students`、`homeworks`、`grades` 增加服务端分页参数：`page`、`pageSize`、`total`。
- 为题库知识点卡片新增聚合接口（如 `GET /questions/stats?keyword=`），由数据库 `GROUP BY knowledge_tag` 返回各知识点数量/题型数量，避免全量传输。
- `GradeInput.vue` 可改为“学生分页 + 成绩按学生查询”，或使用服务端聚合返回每个学生的考试次数和最近成绩。
- `HomeworkView.vue` 查询时传 `status=published`，不要拉全量再 `filter`。

**涉及文件**：

- `server/src/controllers/question.controller.js`
- `server/src/controllers/student.controller.js`
- `server/src/controllers/homework.controller.js`
- `server/src/controllers/grade.controller.js`
- `client/src/views/question/QuestionBrowse.vue`
- `client/src/views/question/QuestionBank.vue`
- `client/src/views/grade/GradeInput.vue`
- `client/src/views/homework/HomeworkView.vue`

---

### 6. HTML 渲染安全（XSS 防护）

**现状**：

- `RichContent.vue` 使用 `v-html` 直接渲染后端/AI 返回的 HTML。
- `printHtml.ts` 和 `GradeAnalysis.vue` 的 `printFeedback` 会把富文本/评语写入新窗口 HTML。
- 如果富文本包含 `<script>`、`onerror` 等，可能形成 XSS 或打印页被注入。

**建议**：

- 引入 `dompurify`，在 `RichContent` 渲染前对 HTML 做 `DOMPurify.sanitize()`。
- 在 `printHtml` 的 `renderMathHtml` 中先净化再交给 KaTeX。
- 教师评语、学生姓名等纯文本字段插入 HTML 前必须 `escapeHtml`（已有部分处理，需覆盖 `printFeedback` 的评语）。
- 后端保存富文本时也可统一做白名单清洗（服务端二次防线）。

**涉及文件**：

- `client/src/components/RichContent.vue`
- `client/src/utils/printHtml.ts`
- `client/src/views/grade/GradeAnalysis.vue`
- `client/src/views/conclusion/ConclusionList.vue`

## 三、中优先级

### 7. 用数据库迁移替代启动时 `sync({ alter: true })`

**现状**：`server/src/index.js` 每次启动执行 `sequelize.sync({ alter: true })`，在开发期方便，但生产环境可能误改表结构、长时间锁表、或掩盖迁移历史。

**建议**：

- 引入 `sequelize-cli` + migrations（或 `umzug`），把建表/加列/加索引改为版本化迁移。
- 开发环境可保留 `sync`，生产环境启动时不自动 `alter`。
- 将 `ensureIndexes` 中的索引迁移到 migration 中，作为可重复执行的历史记录。

**涉及文件**：`server/src/index.js`、`server/src/utils/ensureIndexes.js`。

---

### 8. 作业/学生的多对多关系规范化

**现状**：`Homework` 使用 JSON 数组 `questionIds`、`studentIds` 存多对多关系。优点是简单，缺点是无法用 SQL 做关联查询、无法保证外键完整性、大数据量下 JSON 字段不便统计。

**建议**：

- 新增 `homework_questions`、`homework_students` 关联表。
- 题目详情、导出、成绩录入改为通过关联表查询。
- 如果短期内不想大改，可先给 JSON 数组加长度限制，并在应用层保证 id 存在。

**涉及文件**：

- `server/src/models/Homework.js`
- `server/src/models/Submission.js`
- `server/src/controllers/homework.controller.js`

---

### 9. 缓存失效与聚合下推

**现状**：

- `server/src/utils/cache.js` 是进程内 Map + TTL，写入接口不会主动清缓存；首页统计、题目标签等最长 10s 内可能看到旧数据。
- `grade.controller.summary` 把筛选后的全量成绩拉到 Node 内存做分布/对比/趋势，数据量大时内存和 CPU 都会上升。

**建议**：

- 给 `cache` 增加 `cacheDel(key)` / `cacheDelByPrefix(prefix)`，在创建/更新/删除题目、成绩后主动失效相关缓存。
- 分数段、班级平均等聚合尽量用 SQL `GROUP BY` / `COUNT` / `AVG` 完成，Node 只做少量组装。
- 若需缓存，使用 Redis 或至少支持多实例共享（当前单机可暂缓）。

**涉及文件**：

- `server/src/utils/cache.js`
- `server/src/controllers/stats.controller.js`
- `server/src/controllers/question.controller.js`
- `server/src/controllers/grade.controller.js`

---

### 10. 作业评分与成绩导入的批量写优化

**现状**：

- `homework.controller.score` 对每个学生循环 `findOrCreate` + 可能 `save`，N 个学生 = N 次查询 + N 次写入。
- `grade.controller.import` 虽然避免了逐条 `findOne`，但会 `ExamScore.findAll()` 全表加载，且更新仍是逐条 `update`。

**建议**：

- 作业评分：先用一次查询取出该作业已有 `Submission`，再区分新增/更新；用事务包裹，必要时 `bulkCreate(..., { updateOnDuplicate: ['score'] })`。
- 成绩导入：按当前筛选或唯一键只加载相关记录；利用 MySQL `INSERT ... ON DUPLICATE KEY UPDATE` 或 Sequelize `bulkCreate` 的 `updateOnDuplicate`。

**涉及文件**：

- `server/src/controllers/homework.controller.js`
- `server/src/controllers/grade.controller.js`

---

### 11. 前端公共逻辑抽取

**现状**：

- 多个页面重复实现 `formatDateTime`、`typeLabel`、`stripHtml`、`escapeHtml`。
- `Dashboard.vue` 和 `GradeAnalysis.vue` 重复 echarts 初始化/resize/dispose 逻辑。
- `QuestionBrowse.vue`、`KnowledgeQuestions.vue`、`ConclusionList.vue` 的打印 HTML 模板分散。

**建议**：

- 新建 `client/src/utils/format.ts`：日期格式化、题型映射、HTML 清洗/转义。
- 新建 `client/src/composables/useECharts.ts`：封装 `init/setOption/resize/dispose`，减少重复代码。
- 打印 HTML 可抽成模板函数，统一处理标题、页眉、公式渲染、样式注入。

**涉及文件**：

- `client/src/views/**`
- `client/src/components/RichEditor.vue`
- `client/src/utils/printHtml.ts`

---

### 12. 生产部署与安全加固

**现状**：

- `app.use(cors())` 允许所有来源；适合本机开发，不适合部署到局域网/公网。
- 缺少 `helmet`、请求压缩、访问日志、限流。
- `errorHandler` 直接返回 `err.message`，可能泄露内部路径或数据库信息。
- 前端 `/api` 代理硬编码 `http://localhost:3000`。

**建议**：

- 增加 `NODE_ENV` 判断，生产环境限制 CORS 白名单。
- 安装并使用 `helmet`、`compression`、`express-rate-limit`、`morgan`（或 pino）。
- 生产环境错误响应统一为“服务器内部错误”，详情只写日志。
- Vite 代理目标改为 `process.env.VITE_API_TARGET`，生产构建用 `VITE_API_BASE_URL`。

**涉及文件**：

- `server/src/app.js`
- `server/src/middlewares/errorHandler.js`
- `client/vite.config.ts`

---

### 13. AI Key 与 AI 请求体验

**现状**：API Key 存在浏览器 `localStorage`，请求时由前端传给后端调用第三方接口。单机自用可以接受，但若部署到多人环境，Key 会暴露给所有浏览器用户。

**建议**：

- 如果只是个人使用，可把 Key 移到 `server/.env`，由后端读取，前端不保存 Key。
- 如果保留前端配置，至少把 `/api/ai/format` 限制为本地访问或加访问口令。
- 可把 AI 排版改为 SSE 流式输出，减少长等待的“无响应感”。
- 对 AI 返回 HTML 做清洗后再写入编辑器（与第 6 点一致）。

**涉及文件**：

- `server/src/controllers/ai.controller.js`
- `client/src/utils/aiConfig.ts`
- `client/src/views/system/SystemSettings.vue`
- `client/src/components/RichEditor.vue`

---

### 14. 前端类型化

**现状**：大量 `ref<any[]>`、`reactive<any>`、API 函数 `params?: any`，TypeScript 收益有限。

**建议**：

- 在 `client/src/types` 或 `api/types.ts` 定义 `Student`、`Question`、`Homework`、`Submission`、`ExamScore`、`Conclusion` 等接口。
- API 函数使用泛型返回 `Promise<T>`。
- 逐步替换 `any`，至少覆盖核心 CRUD 和表单。

**涉及文件**：

- `client/src/api/*.ts`
- `client/src/views/**`
- `client/src/components/QuestionFormDialog.vue`

---

## 四、低优先级 / 体验与工程化

### 15. wxapp 目录清理或完善

**现状**：`wxapp` 是 uni-app 默认模板，只有一个 Hello 页面，未接入根 workspace，也没有实际业务。保留会造成“项目里有个未完成小程序”的困惑。

**建议**：

- 若近期不做小程序：从仓库移除 `wxapp` 或在 README 标注“预留模板，未启用”。
- 若要做学生端：规划“查看作业/提交答案/查看成绩”等页面，并复用后端接口；同时将 `wxapp` 纳入 pnpm workspace 或独立说明文档。

**涉及文件**：`wxapp/**`、`pnpm-workspace.yaml`。

---

### 16. 增加 lint / format / test / CI

**现状**：项目没有 ESLint、Prettier、单元测试、E2E、CI 配置。

**建议**：

- 前端：`eslint + vue/ts` 规则、`prettier`。
- 后端：`eslint` + 基础单元测试（supertest 测 API）。
- 根目录加 `lint`、`test` 脚本。
- 配置 GitHub Actions / 其他 CI：`pnpm install -> pnpm build -> pnpm lint -> pnpm test`。

**涉及文件**：`package.json`、`client/package.json`、`server/package.json`。

---

### 17. 构建体积继续优化

**现状**：已做路由懒加载和 `manualChunks` 分包，但 `element-plus` chunk 仍较大（约 800KB 级别），`echarts` 也约 500KB 级别。

**建议**：

- 引入 `unplugin-vue-components` + `unplugin-auto-import` 自动按需引入 Element Plus，减少手动维护 `main.ts` 组件清单。
- ECharts 已使用 `echarts/core`，可进一步按需注册，并把图表组件封装成异步加载。
- 考虑 `vite-plugin-compression` 生成 gzip/brotli，或由 Nginx/CDN 开启压缩。
- 使用 `rollup-plugin-visualizer` 分析体积，确认哪些依赖值得优化。

**涉及文件**：`client/vite.config.ts`、`client/src/main.ts`。

---

### 18. 补充 README 与运行文档

**现状**：根目录有 `启动.bat`，但没有 README；新接手者需要从 `docs/PLANNING.md` 推断启动方式。

**建议**：

- 增加根目录 `README.md`：项目简介、目录结构、环境要求、启动步骤、构建部署、备份恢复说明。
- 补充 `.env.example` 的字段说明和 OSS 配置步骤。

## 五、建议实施路线

| 阶段    | 内容                                    | 预计收益                         |
| ------- | --------------------------------------- | -------------------------------- |
| 第 1 步 | 统一请求错误处理、输入校验、XSS 清洗    | 提升稳定性与安全性，改动小见效快 |
| 第 2 步 | 备份补全、数据库唯一约束、分页/聚合接口 | 数据更可靠，规模增长不卡顿       |
| 第 3 步 | 迁移替代 sync、批量写优化、缓存失效     | 生产部署更安全，性能更好         |
| 第 4 步 | 类型化、公共逻辑抽取、lint/test/CI      | 提升可维护性与协作效率           |
| 第 5 步 | 构建体积、小程序、README 等体验工程     | 完善交付物与长期演进基础         |

## 六、验收清单

- [ ] 所有前端请求失败都有统一用户提示，不再出现未处理 Promise rejection。
- [ ] 所有写接口只接受白名单字段，非法输入返回 4xx 业务错误。
- [ ] 备份 ZIP 包含全部业务表，并提供可用的恢复流程。
- [ ] `exam_scores`、`submissions` 有唯一约束，重复提交不会产生脏数据。
- [ ] 题库、学生、作业、成绩列表支持服务端分页，题库卡片统计走聚合接口。
- [ ] 富文本展示和打印均经过 HTML 净化。
- [ ] 生产环境不使用 `sync({ alter: true })`，CORS/错误信息/日志满足部署要求。
- [ ] 核心页面类型定义齐全，`any` 数量明显下降。
- [ ] `pnpm lint`、`pnpm test`、`pnpm build` 均可通过。
